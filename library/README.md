# Effect library

Every magick Effect from the two M20 rulebooks as structured data, in our own words:

- *Mage: The Ascension 20th Anniversary Edition* (M20)
- *How Do You DO That? A Practical Guide to Sphere Magick* (HDYDT)

`effects.json` is what the app ships. It holds **our own summaries** plus book and page
references, never book text: the app is public. The books themselves and every bit of text
pulled out of them stay in `refs/`, which is gitignored.

## Files

| Path | What |
| --- | --- |
| `effects.json` | the dataset (generated by `build.mjs`, committed) |
| `src/*.json` | hand-written batches, one per book section; edit these, not `effects.json` |
| `tags.json` | the allowed tags, with what each one covers |
| `whitelist/*.json` | accepted check hits, each with a reason (optional; one file per batch) |
| `scripts/extract-text.mjs` | rulebook PDFs -> `refs/text/<book>/pNNN.txt` (one file per PDF page, plus `-layout` versions) |
| `scripts/build.mjs` | `src/*.json` -> `effects.json` (fills `pdfPage`, sorts, fixes key order) |
| `scripts/check.mjs` | coverage report against the book text; must end in `OK: 0 issues` |
| `scripts/find.mjs` | which page a phrase is on, for filling in sources |
| `scripts/spotcheck.mjs` | random entries next to their book passage, for a human check (local only) |
| `scripts/stats.mjs` | rewrites the counts at the bottom of this file |

## Running it

Needs Node 18+ and `pdftotext` (poppler; the mingw64 one in Git for Windows works). The PDFs
are read from `refs/` in the repo, or from the main checkout's `refs/` when run in a git
worktree; set `AGATHON_REFS` to point elsewhere.

```sh
node library/scripts/extract-text.mjs   # once: book text into refs/text (gitignored)
node library/scripts/build.mjs          # src/*.json -> effects.json
node library/scripts/check.mjs          # report; exit code 1 if anything is left
node library/scripts/check.mjs --src hdydt-time   # just one batch, while writing it
node library/scripts/check.mjs --verbose          # also list inferred ranks and whitelisted hits
node library/scripts/spotcheck.mjs m20-spheres --n 10 --seed 1   # -> library/.spotcheck/ (gitignored)
node library/scripts/stats.mjs          # refresh the counts below
```

### What the check covers

| Check | Meaning |
| --- | --- |
| `schema` | required fields, known Spheres, kinds, tags and vulgarity values, ranks 1-5, no empty combos |
| `pages` | every source has a printed page, and its `pdfPage` is page + the book's offset (1 for both books) |
| `spheres` | every printed Sphere+rank of an entry is stated on its page or a neighbouring page, and the Spheres of one combo are stated within 700 characters of each other |
| `ranks` | the rank entries cover all 9 Spheres x 5 ranks |
| `duplicates` | ids and names are unique (names case-insensitive) |
| `text` | shipped text is plain keyboard ASCII: no em/en dashes, curly quotes or other typographic characters |
| `copies` | no run of 8 or more words in our text matches the book text of the page window |
| `whitelist` | no stale whitelist entries |

The `spheres` check understands the book notations: `Forces 3`, `Forces 2+`, `Life 2 (3)`
(self and others), `Forces or Matter 3`, `Life, Matter, or Forces 2`, `Mind 3/ Forces 2`,
`Mind 1-3`, `Spirit 2 or 3`, `Rank 3 Forces`, `three dots of Forces`, the Technocratic names
(Data, Primal Utility, Dimensional Science), and the dot headers of the M20 rank lists. A rank
entry must have its book heading right after the right number of dots. Feats taken from a rank
list (section `Spheres: X`) may take the rank of Sphere X from the dot header.

Known limit: a wrong rank for a Sphere that the same page also mentions at that rank for
another reason is not caught. The spot-checks are there for that.

## Schema

```ts
type Sphere = 'Correspondence' | 'Entropy' | 'Forces' | 'Life' | 'Matter' | 'Mind' | 'Prime' | 'Spirit' | 'Time';
type Spheres = Partial<Record<Sphere, number>>; // Sphere -> minimum rank 1-5

interface Effect {
  id: string;            // stable kebab-case slug, unique
  name: string;          // unique; rank entries are "<Sphere> <n>: <book heading> / ..."
  kind: 'rank' | 'feat' | 'rote';
  summary: string;       // our own words, 1-3 sentences: what it does
  system?: string;       // our own words: successes, difficulty, duration, damage, costs
  combos: {              // alternatives: any one combo is enough
    spheres: Spheres;    // within a combo every Sphere is needed at >= that rank
    note?: string;       // what this alternative is for ("on yourself", "fire or wind")
    inferred?: Sphere[]; // Spheres the book names without a rank (see below)
  }[];
  optional?: {           // add-ons that change or improve the Effect
    spheres: Spheres;
    purpose: string;
    inferred?: Sphere[];
  }[];
  coincidentalIf?: string; // only when the book says how it stays coincidental
  vulgarity?: 'coincidental' | 'vulgar' | 'depends'; // only when the book says
  tags: string[];          // from tags.json
  source: {
    book: 'M20' | 'HDYDT';
    page: number;        // printed page number
    pdfPage: number;     // PDF page (filled in by build.mjs: page + 1 in both books)
    section?: string;    // book section, e.g. "Spheres: Forces", "Elemental Mastery: Weather-Witching"
  }[];
}
```

Kinds:

- `rank`: what one dot of a Sphere does in general (the M20 rank lists, including the
  Technocratic Data, Dimensional Science and Primal Utility lists, which are stored under their
  mystic Sphere and tagged `technocracy`).
- `feat`: a worked Effect with its own Sphere requirements, from either book.
- `rote`: a named rote, Procedure or Adjustment (M20 pp. 601-611).

Sphere names are always the Tradition ones (Correspondence, Prime, Spirit). The Technocratic
names (`data:`, `primal:`, `dimsci:`) are search aliases for the app.

## Writing entries

The books have no rote list: Effects sit in running prose, often with alternatives. Extraction
is reading section by section, not a regex job.

- **One entry per distinct Effect.** Variants of the same Effect go into `combos` with a
  `note`; extras that improve it go into `optional` with a `purpose`.
- **Alternatives become separate combos.** "Forces or Matter 3" is two combos.
  "Entropy 2, Forces 2, or both" is three. "Life 3, Prime 3, and Forces or Matter 3" is
  `{Life 3, Prime 3, Forces 3}` and `{Life 3, Prime 3, Matter 3}`.
- **Self and others.** "Life 2 (3)" means Life 2 on yourself, Life 3 on someone else: two
  combos with notes.
- **"Forces 2+"** is a minimum: store rank 2 and say in the summary or system that more rank
  does more.
- **Inferred ranks.** When the book names a Sphere without a rank ("by adding Life or
  Matter"), pick the lowest rank that can do it by the M20 rank lists (usually 2 to work on a
  Pattern, 1 to perceive it) and list that Sphere in `inferred`. The check skips inferred
  ranks and lists them with `--verbose`; the app can show them as approximate.
- **Pages.** `page` is the printed page where the Sphere ranks are stated. Add a second
  source when an Effect spans pages or is described in both books.
- **Our own words.** Summaries are short and practical, written fresh: no copied sentences,
  no paraphrase that follows the book sentence by sentence. Keep the numbers (successes,
  difficulties, damage) since rules are facts, but say them our way.
- **Plain keyboard characters only** in every text field: straight quotes, plain hyphens,
  three dots instead of an ellipsis character, no em or en dashes.
- **Vulgarity and coincidence** only when the book says so.
- Leave out things a mage does not cast: creature powers, spirit Charms, Wonders and
  character-creation examples.
