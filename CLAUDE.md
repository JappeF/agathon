# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Agathon: an offline-first PWA (React 18 + TypeScript + Vite + vite-plugin-pwa) for Mage: The Ascension 20th Anniversary (M20). All decisions and the build order are in `BRAINSTORM.md` (Dutch); read it before adding features. Nice-to-haves, ideas and open points are GitHub issues on OWNER/agathon with emoji labels (kind: ✨ nice to have, 🗺️ roadmap, 💬 to discuss, ⏳ needs input; topic: 🔮 AI, 📜 sheet, 🪄 spells, 📚 library, 🎲 at the table, 🤝 sharing, 📱 android...); reuse those labels for new issues.

The app is a helper and sounding board, not a rules engine: dice are rolled outside the app. The core is a searchable library of spells (magick effects; the UI says spells, the code and data say effects; own summaries, never book text), character sheets imported from Mr. Gone PDFs, sharing, and spell dossiers with a copyable "context pack" prompt for any AI, which can quote the player's own rulebook pages (phase 4 in `BRAINSTORM.md`). App language is English. `README.md` is the public overview (screenshots in `docs/`); the code is MIT (`LICENSE`).

## Commands

```sh
npm run dev      # Vite dev server (localhost:5173)
npm run build    # tsc -b && vite build -> dist/ (also regenerates the service worker precache)
npm run preview  # serve dist/ on localhost:4173
npm run deploy   # build + wrangler pages deploy dist --project-name agathon
npm run icons    # public/icons/sigil.svg -> PNG app icons via sharp

node scripts/verify.mjs        # headless-Edge checks: shell, nav, IndexedDB persistence, character switcher, pick lists, Android file pickers, 320px edit mode, 344px mini bar on one line, SW, offline reload, desktop bar that doesn't move
node scripts/verify-sheet.mjs  # import the sample Mr. Gone PDF via the UI, trackers, edit mode, XP, favorite spells, PDF export round trip, re-import diff, copy character, blank sheet (Reader extensions dropped, app portrait drawn)
node scripts/verify-library.mjs  # Sphere bar and exact combinations, operators, tags, detail with difficulty and checklist, deep links, castable + one dot away
node scripts/verify-share.mjs  # share link, QR, file without notes, import on a second browser context, name clash, damaged link, back up all
node scripts/verify-books.mjs  # own rulebooks: both PDFs read and recognised, other PDFs refused, pages in Copy for AI, index file round trip (needs the rulebook PDFs in refs/)
node scripts/verify-spells.mjs # spell dossiers: start from a library spell or by name, Spheres and difficulty, versions, linked effects, the log, Copy for AI and pasting an answer back, persistence, deleting
BASE=https://agathon.pages.dev node scripts/verify.mjs   # any verify script against the live site
node scripts/screenshots.mjs   # regenerate docs/ screenshots with a demo character seeded through a share link (never real sheets or photos)

node scripts/sigil.mjs         # regenerate public/icons/sigil.svg (seeded sparking portal ring), then npm run icons
node scripts/build-mrgone-map.mjs <sheet.pdf>   # regenerate src/sheets/mrgone-m20-2page.json from a Mr. Gone sheet
node scripts/sheet-words.mjs <sheet.pdf>        # dump a sheet's printed words with positions (pdf.js), for building maps
```

`verify-sheet.mjs` and `verify-library.mjs` need the sample sheet in `refs/` (gitignored); override with `SHEET=<path>`. verify-sheet also uses a blank sheet, `refs/M20_2-Page_Interactive.pdf` (`BLANK=<path>`), falling back to the sample. `verify-books.mjs` needs the two rulebook PDFs there (`M20=`, `HDYDT=`). CI (`.github/workflows/ci.yml`) builds and runs `verify.mjs`, `verify-share.mjs` and `verify-spells.mjs`, the ones that need no sheet.

The spell library (563 entries from M20 and How Do You DO That, our own summaries with book/page refs; every entry was read side by side with its pages in issue #18) lives in `library/`; `library/README.md` has the schema, authoring rules and counts. Edit `library/src/*.json`, then:

```sh
node library/scripts/extract-text.mjs   # once: book text into refs/text (gitignored)
node library/scripts/build.mjs          # src/*.json -> library/effects.json (committed)
node library/scripts/check.mjs          # must end in "OK: 0 issues"
```

No unit tests or linters; verify scripts (playwright-core driving system Edge via `channel: 'msedge'`) are the verification story. The preview server must be running on :4173 first.

## Architecture

- **Storage:** everything the player owns lives in IndexedDB via Dexie (`src/db/db.ts`): `characters`, `spells`, `books` (page text of the player's own rulebook PDFs, never shipped or shared). `requestPersistence()` asks for persistent storage on the first real write. Use `useLiveQuery` (dexie-react-hooks) in components.
- **Routing:** hash routes in `useHashRoute.ts`: `#/library`, `#/spells`, `#/spells/<id>`, `#/characters`, `#/characters/<id>/<tab>` (tabs magick, traits, background, notes). `activeCharacter.ts` remembers the character in play (localStorage, opening a sheet sets it); `useActiveCharacter()` gives all characters plus the active one (falling back to the most recent) and re-renders on a switch. `#/characters` without an id is not a list: it redirects to the character in play, or is the welcome page (add/import) when there are none.
- **Characters:** `character.ts` is the full M20 model (all Attributes/Abilities in `traits`, Spheres, the Q/P wheel, health marks, backgrounds, merits/flaws, rotes, focus, wonders, description, gear, weapons, notes). `clampWheel` enforces M20 p. 331: Paradox cancels Quintessence where they meet, Quintessence stops at the Paradox. `CharacterSheet.tsx` keeps a local copy and debounces writes (`useDraft.ts`, shared with the spell dossier: flushed on unmount and when the page is hidden, and a newer stored row, such as an import from the character menu while this sheet is open, is taken over whenever no write is pending; local edits bump `updatedAt` so a late echo of an earlier save never undoes typing); `App.tsx` keys it by id, so switching characters starts fresh (play mode, no dialog left open; a delete confirmation once stayed open for the next character). Its header shows a 128px portrait (tap = enlarged view; in edit mode tap = replace) with name, concept line (concept, sect or else affiliation, essence; the character menu and import previews sum a character up the same way), the XP field and the status pills beside it (below 600px: a 96px portrait, and the pills drop to their own full-width row via `display: contents` on `.sheet-title`, because beside the portrait they wrapped). Experience is a plain number: the XP field takes digits only and stays editable in play mode, and the Mr. Gone import keeps only the number ("4 exp" becomes "4"); when that header scrolls out of view (IntersectionObserver) a fixed mini bar with a small portrait and the same pills takes over, so health and Willpower stay in reach. The mini bar has its own drop-down (`miniOpen`) instead of reusing the in-flow trackers panel: moving that panel between the two places changed the page height, which flipped the observer back and forth and blocked scrolling. `html` has `scroll-padding-top` so nothing scrolls in under that bar; "show Abilities at 0" is remembered per device (`agathon:show-untrained`); play mode only lets the trackers change (health, Willpower spent, Q/P), the lock button switches to edit mode. "Copy character" in the sheet's menu (`copyCharacter` in db.ts) copies the character with its stored PDF and spell ideas under a free name ("X (copy)", "X (copy 2)"; a copy of a copy counts on from the original name) and opens it.
- **Sheet import/export:** `src/sheets/mrgone.ts` reads and writes Mr. Gone's fillable M20 2-page sheet with pdf-lib (lazy-loaded). Its dot checkboxes have meaningless names, so `mrgone-m20-2page.json` (generated by `scripts/build-mrgone-map.mjs` from field positions next to the printed labels; all 625 fields mapped, none twice) says which field is which trait. A lone `x` after a Sphere marks the affinity Sphere. The imported PDF is kept per character in the `sheetFiles` table so "Export PDF sheet" fills that same file. Characters made in the app use one blank sheet per device (`sheetFiles` row `__blank__`): the first export asks for it, with a download link to Mr. Gone's M20 2-page interactive sheet (`MRGONE_BLANK_URL`). We don't ship it (publisher logo and Mr. Gone's work, no terms for hosting it elsewhere) and his server sends no CORS header, so the app can't fetch it either. On export, check boxes keep the sheet's own appearances: Mr. Gone's boxes only have an "on" look (/Yes) and pdf-lib treats the missing "off" look as a fault and redraws every box as a square with a check mark, so `writeMrGone` saves with `updateFieldAppearances: false` and only redraws text fields and drop-downs itself, in Times Bold (the sheet's Goudy Old Style can't be reused) with auto size capped at 12pt like Acrobat, keeping each field's DA. verify-sheet checks the boxes' looks; to eyeball an export, `node scripts/render-pdf-page.mjs <pdf> <png> [page]` renders it with pdfjs-dist in Edge. Mr. Gone's blank sheet is Reader extended (`/Perms /UR3`, an Adobe signature over the exact bytes): any rewrite breaks it and Acrobat Reader then switches the form off, so `writeMrGone` drops `/Perms`. The sheet has no portrait box; when the PDF holds no portrait (`findPdfPortrait`), export draws the app's one as JPEG (`portraitJpeg`) at `PORTRAIT_BOX` on page 2, over the right side of Description, where players put theirs. When the PDF has one and the app portrait differs from what import makes of it (`imageToPortrait` of the PDF picture, compared as data URLs; `sheetPortrait` in sheetActions), export swaps the pixels of that same image object, cropped to its shape, so it keeps its place and size. A portrait removed in the app leaves the PDF's picture alone. Re-importing shows `diffSheet` changes first and keeps id, notes and spells (`sheetActions.ts`). Matching on import is by character name.
- **Library UI:** `src/library/data.ts` lazy-loads `library/effects.json` as its own chunk (precached). `src/library/search.ts` parses the query: text, quoted phrases and `-exclusions`, Sphere operators (`mind:3` = up to 3, `=3`, `3+`, `2-4`; any 3+ letter prefix; `data:`/`primal:`/`dimsci:`), `uses:` (these Spheres plus others), `tag:`, `book:`, `kind:`, `is:` (also `is:fav` for favorites), `name:`. A Sphere query matches a combo with exactly those Spheres unless `uses:` or "Allow other Spheres" is on. With "What <character> can cast" on, hits are split by `deficit` (dots missing over the closest combo): castable now, and a separate "One dot away" section. The Sphere bar, tag rows and book chips just rewrite the query text (`toggleOp`), so the query stays the single source of truth. Cards (`EffectCard`) show only the first (best matching) combo plus "+N more", so they all have the same shape; the edge strip takes the colour of that combo's highest Sphere, and hovering lets portal sparks rise off the card (no lift, no sweep). Search words (free text, phrases, `name:`) are marked with `<mark>` (`Highlighted.tsx`, after another app): in the name, in the summary (cut around the first hit by `snippet` so it shows within the 3-line clamp), and, when the words only occur further down (system, combo note, add-on purpose, coincidental note), in an extra `.effect-match` line that shows why the card matched. The detail marks them too and lights up the tags the search filters on. Layout: three grid areas (search, side, results); on phones they stack and the book/tag filters hide behind a Filters button, from 900px the side becomes a sticky another app-style sidebar (Spheres as a 3x3 grid with names, tags as rows with counts) next to a multi-column card grid. `EffectDetail.tsx` shows the combos (pick one), the base difficulty from M20 p. 501 (highest Sphere +3 / +4 / +5), the book's coincidental note and a mitigation checklist; Sphere tricks in it only light up when the active character has the dots. Routes: `#/library/<effect id>`; closing goes back only when the detail was opened from the list, so deep links never leave the app.
- **Spell dossiers** (the "Spell ideas" tab; the route is still `#/spells`, and the library calls its entries spells, never effects): `spells.ts` is the model (`Spell`: title, goal, linked effect ids, `versions` oldest first with the last one being the plan, `log` of castings) stored in the `spells` table (rows from before only had a title; `normalizeSpell` fills them in on read). `SpellsView.tsx` is the list of the active character's ideas and the dossier, which saves debounced like the sheet and is always editable (a working document, no lock). A version's Spheres use the library's Sphere bar (tap raises, past 5 back to 0); base difficulty comes from `difficulties()` in `library/search.ts`, shared with the effect detail. "Try another way" copies the plan into a new version; versions are numbered by creation time, so "Make this the plan" (moving one to the end) keeps the names. The effect detail's "Start a spell idea from this" (`spellActions.ts`) takes the effect name, link and selected combo. The Magick tab lists the character's ideas; deleting a character deletes them. Dossiers are not part of shares yet.
- **Context pack (Copy for AI):** `contextPack.ts` builds one Markdown prompt on the device: a role (think along as an M20 player and Storyteller, the ST decides, say so when unsure of a rule), the mage (traits, Spheres, focus, favorite spells; private notes only when ticked), the idea and its plan with base difficulty, optionally earlier versions and the log, the linked library effects (our summaries with book pages), a few rules we are sure of (p. 501 difficulty, p. 331 wheel), the player's scene or question, and a fixed ask that ends in a JSON block (`{"agathon": "version", "spheres": {...}, "how", "coincidental", "notes"}`). Nothing is sent anywhere; the player pastes it into their own AI. "Paste the answer" (`parseReply`) scans every balanced `{...}` in the answer (fenced or not, spread over lines, any label in "agathon", as Gemini does), takes the last one that holds Sphere ranks (the `spheres` key, else any key mentioning Spheres at any depth, like `mechanics.spheres_required`, else any object of Sphere ranks), fills how/coincidental/notes from those keys or the nearest look-alikes (`intent`, `instrument`, `bottleneck`...), keeps only known Sphere names with ranks 1-5 and the three text fields, and adds it as a new version marked `source: 'ai'` with the whole answer kept in `reply`. The dialog's toggles are remembered per device (`agathon:pack`); the question starts empty.
- **Own rulebooks (book index):** `books.ts` reads the player's M20 or HDYDT PDF with pdfjs-dist (lazy chunk, worker via `?url`, precached as `.mjs`) into page text, recognised by the first pages' text with spaces removed (HDYDT first: it also says "20th Anniversary") and the page count; anything else is refused. Only the text goes into the `books` table (index = PDF page - 1), with `offset` (pdf page = printed page + offset) voted from the footers, which pdf.js puts first with the number stuck on ("501Chapter Ten..."); the PDF itself is not kept. Book text never ships, never goes into shares. `BooksPanel.tsx` (bottom of the Spell ideas list) adds and removes books and saves/loads the index as a private `agathon-books.json`, so a phone can skip reading the PDF. In Copy for AI, `candidatePassages` offers the linked effects' pages, the Sphere rank pages the plan uses (library ids like `forces-3`) and the core rules pages (M20 501-503, 530, 547-548); the first 15 are ticked, the player can change that, and ticked pages are quoted in full in the pack.
- **Pick lists (Backgrounds, Merits, Flaws, Concept, Essence, Nature, Demeanor, Affiliation, Sect, specialties):** `sheetLists.ts` holds the ones M20 defines (names, Technocratic names, costs, types, pages from the book; one-line hints in our own words). In edit mode "Add background/merit/flaw" opens `TraitPicker.tsx`: search over names, Technocratic names and hints, tap to add (Backgrounds at one dot, Merits and Flaws at their lowest cost), or add the typed name as your own. Characters whose affiliation or sect reads as Technocratic get the Union's names (Laboratory, Genius...). Concept, Essence, Nature, Demeanor, Affiliation and Sect are `PickField`s (`CONCEPTS` with the book's examples as hints, `ESSENCES` with Pattern also called Static, `ARCHETYPES` for both Nature and Demeanor): free text plus a button that opens the same picker in `mode="set"` with M20's three Affiliations and 25 Sects (Traditions, Conventions, Crafts, with their other names and pages); the Sect list follows the Affiliation (`affiliationOf`), and picking a Sect with no Affiliation fills that in. Specialty inputs suggest `SPECIALTIES` through a `<datalist>` per trait (rendered once in edit mode): M20's suggested specialties first, then ours. Rows stay free-form text; in play mode a known name has its hint and page as a tooltip.
- **Favorite spells:** `Character.pinned` holds library effect ids (the field name is older than the wording). Like `portrait` it is app-owned: left out of `SheetFields`, so PDF import/export and `diffSheet` never touch it; shares carry it (sanitized to id-like strings). Every library card has a star (a sibling of the card button, as in another app, since buttons can't nest) and the effect detail has the same star (`.detail-fav`); both toggle via `togglePinned` (exported from `LibraryView.tsx` with `searchLibrary`). "Only <name>'s favorites" toggles `is:fav` in the query (`is:pinned` still works). The Magick tab's "Favorite spells" block lists them (best castable combo shown) and opens `EffectDetail` over the sheet, so play never leaves the sheet; there the star goes through `patch`. In Agathon rotes are simply favorite spells (`favorites.ts`): `pinned` holds the library ones by id, `rotes` the character's own spells by name. The Magick tab shows both in one list (own spells are added, edited and removed in edit mode); PDF export writes all their names into the sheet's rotes fields, library ones first; PDF import splits the sheet's rote lines with `splitFavorites` (a name in the library becomes a library favorite, a rote winning over a feat of the same name; anything else an own spell) and only ever adds favorites, listing them as "Favorite spells: + name" in the re-import diff. The context pack lists them as favorite spells. The library has no Kind filter either (effects, rotes and Sphere ranks were too close to tell apart); `kind:` still works when typed.
- **Portraits:** `portrait.ts` turns any image into a 640px square data URL (WebP, JPEG fallback for old Safari), cropped a little above centre. On PDF import the largest JPEG that is not a full-page background or a thin strip is taken as the portrait (`portraitFromPdf`, pdf-lib); it only fills an empty portrait, never replaces one set in the app, because `portrait` is app-owned and left out of `SheetFields`/`diffSheet`. Shares carry the full portrait in files and a 128px copy (`shrinkPortrait`, a few KB) in links; QR codes get a separate link without it, because they hold about 2 KB. Incoming ones pass `safePortrait`. `PortalPortrait.tsx` draws it inside a small sparking portal: a CSS ring and glow (cheap for lists) plus the shared `makeSparks`/`SparkLines` from `Portal.tsx`.
- **Sharing:** `share.ts` is the versioned wire format (`app: 'agathon', kind: 'characters', version: 1`), as a `.agathon.json` file or a `#import=<mode>.<base64url(deflate-raw(json))>` link/QR (empty values are dropped to keep links short). Everything from outside goes through `sanitizeCharacter` (known fields only, values clamped) before it touches the database. Shares never carry ids, timestamps or the stored PDF; notes only when ticked. `App.tsx` turns `#import=` links into the `SharedImport` preview; imports only add, a clashing name gets " (2)". The Import button takes both PDFs and character files.
- **Character switcher:** `CharacterMenu.tsx`, mounted once in `App.tsx` and opened with `openCharacterMenu(trigger)` from the nav caret (from 900px) or the "Characters" button on the sheet; the same trigger again closes it. A bottom sheet below 600px, a drop-down anchored under its trigger above that. It stays mounted while hidden, so an import or back-up it started keeps its dialogs; any hash change closes it. `CharacterTools` (add by name, Import, Back up all) is shared with the welcome page.
- **Errors:** `ErrorBoundary` (main.tsx, around App, not around UpdateToast) shows an error screen with Reload instead of a blank page; a failed library chunk load lands there too (`useEffects` throws it, `loadEffects` forgets the failure so a retry can work). Hash segments decode safely (`useHashRoute`). Export throws `NoSheetError` only when there is no PDF; other export errors are shown as they are. Share links stop inflating past 16 MB (`pipe` in share.ts), shared imports are one transaction, and `parseReply` reads only the last 200k characters. Stars toggle against the stored row (`toggleFavorite` in favorites.ts), and operators still being typed (`tag:`, `-name:`) filter nothing.
- **Modals** render through a portal on `<body>` (`Modal.tsx`), so a dialog opened from inside the `<details>` menu survives the menu closing. Modal and the spell detail share `useDialog`: on mount only (onClose lives in a ref, so a parent re-render never pulls focus out of a field), focus moves in unless a field took it with autoFocus, Tab is trapped, Escape closes, and focus returns to the opener or, if that sat in a menu that has closed, to the menu's button. The character menu's triggers carry `aria-expanded`, and the drop-down follows scrolling. Sheet tabs are links in a `nav` with `aria-current`, not an ARIA tab widget. `--ink-faint` is #8a7aa1, the darkest violet that still makes 4.5:1 on every background.
- **PWA:** `registerType: 'prompt'`; `UpdateToast.tsx` (mounted in main.tsx outside App) re-checks hourly and on focus and shows a Reload toast. Its reload falls back to `location.reload()` when the page was never controlled by the service worker (first visit), because `updateServiceWorker(true)` only reloads on a controller change. `public/_headers` keeps index.html/sw.js/workbox/manifest uncached on Cloudflare.
- **Rulebooks and samples** live in `refs/` (gitignored, never commit them or text extracted from them). Only our own summaries are committed.

## Design system

App icon: a sparking golden portal ring (in the spirit of Doctor Strange's portals) on dark violet with a dark violet heart, sparks flying off clockwise, generated by `scripts/sigil.mjs`. The same portal lives, animated, behind the logo (`Portal.tsx`). Violet depths and gilded type in `src/styles.css`: gold `--gold` on violet-black `--bg`, `--paradox` magenta for Paradox; health (the wound pill and the Health track's status) runs green to deep red over the eight wound levels (`.hp-0` unhurt to `.hp-7` Incapacitated, filled), following the penalties and kept clear of the Paradox pink; body text `--ink` is a soft violet-white, never paper white. Fonts self-hosted via fontsource: Cinzel Decorative (logo only), Cinzel (headings), Manrope (UI text), EB Garamond italic (flavor text and quotes only). Animations are CSS-only and switched off under `prefers-reduced-motion`: rising gold Quintessence sparks (`.sparks`), the gilded logo sheen, and the header portal (breathing glow, a glint running clockwise every 9s, seeded sparks flying off clockwise). They run on the compositor, so an idle page leaves the main thread free (verify.mjs checks it stays under 4% of a core; it was 8-13% before): only `transform` and `opacity` of whole HTML elements move. Rules learned the hard way: shapes inside an SVG repaint every frame, so the portal is stacked SVG layers that move as elements (`.portal-glow-layer`, `.portal-glint-layer`); keyframes that use `var()` don't composite, so sparks (`Sparks` in Portal.tsx) are a rotated element holding a box as long as the flight that slides `translateX(100%)`; every iteration start wakes the main thread, so each spark's keyframes hold eight flights per iteration (`FLIGHTS`, the jump back at opacity 0); the logo light is a bright copy of the word in a masked window that slides one way while the copy slides back (`.logo-sheen`), not an animated gradient; the portrait glow is a second shadow on `.pp-ring::after` fading in and out, not an animated box-shadow. `usePauseOffscreen` pauses the header portal and portraits while off screen (`.offscreen`), and portraits under 64px (nav, lists) don't animate at all. To measure: CDP `Performance.getMetrics` TaskDuration over an idle stretch, and a `blink.animations` trace shows any animation that fails to composite. `SphereGlyph.tsx` holds our own line glyphs per Sphere (Entropy a spiral breaking into shards, Mind a brain, Prime a trident over a flared cross, Spirit a little ghost; not the book symbols); reuse it for Sphere chips. Each Sphere has its own colour (`.sph-<Sphere>` sets `--sp`: Correspondence teal, Entropy chartreuse, Forces fire orange, Life green, Matter dark ochre, Mind blue, Prime a light violet-white, Spirit pale violet, Time steel), used by chips, sheet dots and glyphs, the Sphere bar and card edges. Labels are plain sentence case (no tracked all-caps). Mobile first: below 900px the nav is a fixed bottom bar and the portal is a hero behind the logo; from 900px the header (which contains the nav) becomes a compact sticky 72px bar (`--bar-h`) with a small portal, the wordmark and the nav. The library widens to 1400px, the sheet to 1280px. Sheet tabs on wide screens follow the paper sheet: Magick as two columns (Arete and Spheres | wheel, Focus, Favorite spells, Spell ideas, Wonders), Traits as three columns (Physical/Social/Mental, Talents/Skills/Knowledges), Background flowing over 2-3 CSS columns. The nav's third item is the character in play (small portal portrait and name; the name ellipsizes). `html` has a thin violet scrollbar on a transparent track that only appears when the page scrolls, as in another app, and no `scrollbar-gutter` (Edge leaves that reserved strip empty, so the bar stopped short of the window edge; `overflow-y: scroll` drew an empty track with arrows). Instead the page is placed against the whole window: from 900px `.app-main` takes `margin-left: max(0px, (100vw - var(--main-max)) / 2)` (each page sets `--main-max`, not `max-width`), and the bar's right padding subtracts the scrollbar width (`100vw - 100%`), so logo, nav and content don't move when the scrollbar comes or goes. `body` uses `overflow-x: clip`, which never makes it a scroll container, so sticky bars keep working. Measuring scrollbars: Playwright hides them in headless mode, so verify.mjs and verify-library.mjs launch with `ignoreDefaultArgs: ['--hide-scrollbars']` and check positions, not widths; the in-app browser with an emulated size isn't reliable either.

## Gotchas

- `all: unset` on buttons resets `box-sizing`; re-set it after (as in `.btn-icon`).
- File pickers are `FilePick.tsx`: a `<label>` around a real, visually hidden `<input type=file>`, never a `display:none` input clicked from script, and on Android without `accept` when the picker takes JSON (Android greys out .json files; contents are checked anyway). Image and PDF filters stay on Android: without `image/*` it offers camera and files instead of the gallery. A menu holding a picker stays open until a file is chosen (the character menu, the sheet's ⋯ menu). On Android, picking files failed entirely before this; verify.mjs taps Import with an Android user agent and expects a file chooser.
- Text areas grow with their text (`field-sizing: content`, min three lines; `main.tsx` sizes them by hand where that's unsupported). The Notes tab is a full-height notebook with rules that scroll with the text (`.notes-area`).
- The library's sticky sidebar runs from the bar to the window bottom (as in another app), so its divider joins the bar's line. It must stick exactly where it sits (`top: var(--bar-h)`, the library's main has no top padding) and its `-3rem` bottom margin cancels the main's bottom padding; off by a few px it jumps when scrolling starts or ends. verify-library checks it stays put. Its own scrollbar is transparent until hover or focus (`scrollbar-gutter: stable` on the sidebar keeps the space, so nothing shifts).
- Grid columns that hold inputs need `minmax(0, 1fr)`: an `auto` or plain `1fr` column grows to the inputs' natural width (about 20 characters each), which pushed the edit-mode Background tab 70px past a narrow phone. `.tab-body` and `.field` have it; verify.mjs checks every tab in edit mode at 320px.
- The phone nav bar is `position: fixed` inside `.app-header`, which is `isolation: isolate`; the header therefore needs `z-index: 45`, or the page content paints over the nav and its buttons stop working.
- Shipped text uses plain keyboard characters only: no em/en dashes, no curly quotes (house style, same as another app).
- Commit messages end with a line containing only `⚡`, no other trailers.
- Hosting is a classic Cloudflare Pages project (`agathon`, live at https://agathon.pages.dev), created with the hidden `wrangler pages project create --force` flag.
